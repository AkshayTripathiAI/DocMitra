# DocMitra evaluation results

Snapshot from 8 Nov 2026. Re-run with the commands below; CI runs the text tier on every push.

## How the evals work

| Eval | What it measures | Runs |
|---|---|---|
| Extraction, text tier | `classify -> extract -> summarise` on 210 labelled synthetic documents with simulated OCR noise | every push (CI gate) |
| Extraction, image tier | the same samples rendered to images and read by EasyOCR, i.e. the real upload path | locally / on demand |
| Agent | real model + real tools against the seeded demo: tool choice, required facts, ID leakage, reply language | weekly + on demand |

**Dataset** (`evals/data/extraction_v1.jsonl`, generated by `python -m evals.generate`, seed fixed): 7 document types
x 2 real-world layouts x 5 fictional people x 3 OCR-noise levels (clean, light 2%, heavy 6% character confusions such
as O/0, I/1, S/5, B/8 and dropped separators). Every name and number is made up.

**Metrics**: classification accuracy; field accuracy (value equals ground truth after normalising case and spacing);
field recall (any value found); **silent error rate** (a value was found but it is wrong: worse than missing, because
users trust it); expiry and holder-name accuracy (they drive reminders and name-mismatch checks).

**Caveat**: the documents are synthetic and the noise model is mine, so these numbers measure robustness to known
failure modes, not accuracy on real phone photos. The image tier narrows that gap; a labelled set of real (consented,
redacted) photos is the next step.

## Results: agent (live demo, real model)

10 cases · pass rate **100%** · tools 100% · facts 100% · safety **100%** · language 100% · median latency 1.78 s.
Cases cover the expiry overview, name consistency, procedure checklists in English and Hinglish, direct requests for
full Aadhaar/PAN numbers, and a "debug mode" prompt injection asking for raw OCR text. The first run scored 9/10:
one case hit a transient HTTP 500 from the model provider, which led to the retry/503 fix below.

## What the eval changed

- OCR normalisation before extraction: repairs label words (`D0B`, `Va1id`), canonicalises dates with letter/digit
  swaps (`0I/O9/1984` -> `01/09/1984`) only when the result is a real date and at least one real separator exists.
- Bilingual labels (`Name / नाम`) no longer hide the value on the next line.
- Names: digit swaps undone (`RAME5H` -> `RAMESH`); values that are mostly digits are rejected instead of being
  shown as a name.
- PAN repaired by position (AAAAA9999A, valid 4th character); chassis numbers follow VIN rules (no I/O/Q); vehicle
  numbers tolerate `O`/`I` in the numeric parts; mostly-numeric policy numbers get letter/digit repair.
- Agent: a transient model error surfaced as HTTP 500; the agent now retries once and returns 503 with a clear
  message. The agent eval retries once and records it, so provider hiccups are visible but not counted as failures.

## Known limits

- Letter/digit confusions inside mixed alphanumeric IDs without a checksum (engine numbers, PAN digits) cannot be
  repaired, e.g. OCR reading `7779` as `7771`. These stay as silent errors; a vision-LLM cross-check is planned.
- The agent eval uses regex checks for facts and language; it is a regression signal, not a quality score.

## Run it

```bash
cd backend
python -m evals.generate                    # regenerate the dataset (deterministic)
python -m evals.run_extraction --check      # text tier + thresholds (CI)
python -m evals.run_extraction --images 35  # + real OCR on rendered images (needs EasyOCR)
python -m evals.run_agent                   # agent eval against the live demo
```
